## 1. Goal

Stop Claude Code from running network / credential / certificate CLIs directly
(`curl`, `wget`, `nmap`, `masscan`, `certutil`, `cmdkey`, macOS `security`,
PowerShell `Invoke-WebRequest`/`Invoke-RestMethod`). Instead, Claude does the
same work through one audited path — the built-in **WebFetch** tool plus an MCP
server — with an allowlist, per-action approval tiers, hidden credentials, and an
audit log. The point is **redirection, not refusal**: Claude still gets the work
done, just through the governed route.

## 2. Architecture (three cooperating layers)

1. **SessionStart hook** → injects the policy into every session so Claude uses
   the gateway on the first try (avoids hitting a block at all).
2. **MCP server `gw`** (stdio, pure-stdlib Python) → the approved route. Tools:
   `http_request`, `download`, `port_check`, `secret_list`, `secret_use`,
   `cert_inspect`, `file_hash`.
3. **PreToolUse(Bash) hook** → catches direct CLI use (incl. full paths,
   PowerShell aliases `iwr`/`irm`, inline `python -c`/`node -e` network calls)
   and returns the gateway equivalent. `continueOnBlock: true` lets Claude retry
   seamlessly instead of ending the turn.

Optional **deny-rule backstop** (`settings.snippet.json`) for if the plugin is
ever disabled.

## 4. Key design decisions (and why)

- **Pure Python standard library**, no third-party packages. The MCP server is a
  hand-rolled stdio JSON-RPC loop (`src/netgw/mcp_server.py`), config is JSON.
  Rationale: the only dependency is Claude Code + **pixi**; pixi supplies the
  pinned Python so recipients install nothing else. Verify this claim holds — grep
  for any non-stdlib import.
- **`port_check` uses `socket`, not nmap.** It reports TCP reachability of hosts
  the user operates; it is deliberately NOT a scanner (no raw nmap flags, no
  service/version/OS detection). Keep it that way.
- **Secrets by reference.** `http_request(auth_ref="keychain:NAME" | "env:VAR")`
  resolves the value server-side and sets the Authorization header; the value is
  never returned to Claude and is redacted in logs. `secret_reveal` is `refuse`.
- **Single launcher `run.py`** puts `src/` on `sys.path` so the same entry works
  for the MCP server, both hooks, and the CLI (avoids relative-import breakage).

## 5. Approval design (IMPORTANT — the user chose this)

Permission *rules* in settings, not the permission *mode*, are what gate the MCP
tools. Two layers enforce it:

| Tool | settings rule | policy.json tier | Behavior |
|---|---|---|---|
| http_request | allow | auto | never prompts |
| download | allow | auto | never prompts (saves to quarantine, not executed) |
| cert_inspect, file_hash | allow | auto | never prompts |
| port_check | **ask** | auto | prompts once (Claude Code) |
| secret_list, secret_use | **ask** | auto | prompts once (Claude Code); secret_use also needs a `secret_hosts` binding |
| (secret_reveal) | — | refuse | never allowed |

- `allow`/`ask`/`deny` rules are evaluated before accept-edits/"auto" mode, so
  `ask` still prompts in auto mode. **Only full `bypassPermissions`
  (`--dangerously-skip-permissions`) suppresses `ask` prompts;** `deny` always holds.
- The gateway's own `policy.json` mirrors the tiers as a second layer. For an
  `ask` tier the MCP server sends an `elicitation/create` request, i.e. a prompt
  to the **user**. (Earlier versions had a model-settable `approved` flag, which
  let the model approve itself; it has been removed.) If the client does not
  advertise the `elicitation` capability, `ask` actions return `needs_approval`
  and are **not performed**.
- **One prompt per tool (user decision, 2026-10-15):** port_check / secret_list /
  secret_use are `auto` in `policy.json`, because the settings `ask` rule already
  prompts. Use a policy `ask` tier only for tools whose settings rule is `allow`,
  or you get two prompts. Caveat: these three tools now depend on the settings
  rule for their prompt. Without it (another machine, or a missing rule) they run
  unprompted, and `--dangerously-skip-permissions` also skips the prompt.

> **Current design (2026-10-15, supersedes the notes below where they differ):**
> credentials live only in the gateway's vault, managed with
> `/net-gateway:secret` and `/net-gateway:sudo` (values entered in a local
> browser form; commands pass through to Claude without blocking). The
> `keychain:`/`env:` refs, `secret_hosts`, `vault_*` MCP tools, MCP elicitation
> forms and the system dialog were removed. Sudo can be enabled per session or
> for all sessions; when disabled, `run_privileged_confirm` (an `ask` rule) asks
> for each command. See README.

## 6. Things to scrutinize in review

> **Review update (2026-10-15).** Fixed and covered by tests: `auth_ref` is now
> bound to hosts via `secret_hosts` (an unbound ref is refused; this closes
> sending secrets to any host and reading arbitrary `env:` variables); secrets
> echoed back in responses are scrubbed; credentials are dropped on cross-host or
> downgrade redirects; only http(s) URLs are allowed; self-approval via
> `approved` was replaced with elicitation; `secret_list` is now gated;
> `secret_use` works again; audit values are scrubbed; tests use a temp audit log;
> `pixi run server` works. Still open (low): command-check false positives and
> bypasses, `cert_inspect` only reads the leaf certificate and fails on invalid
> certs, `download` has no size cap, logs and quarantine live inside the plugin
> cache.

- **`write_request` is `auto`** (the user wanted `http_request` frictionless).
  That means POST/PUT/DELETE to any host runs without a prompt. With
  `allow_domains: ["*"]` this is a real data-exfiltration surface. Confirm the
  user accepts this, or propose tightening `allow_domains` / setting
  `write_request: "ask"` in `config/policy.json`.
- **The PreToolUse hook is a guardrail, not a security boundary.** It is
  regex-based and can be bypassed (e.g. base64-decoded commands). It reliably
  *steers* Claude; it does not *enforce* against a determined bypass. The user
  explicitly declined OS-level/sandbox enforcement.
- **Redaction** (`policy.py` `redact`, `redact_patterns`) is name-based. Check it
  covers the header/field names you care about.
- **`secret_list` on macOS** parses `security dump-keychain` output (names only).
  Confirm it returns no secret values.
- **Hook latency:** ~0.15s per Bash call (measured). Acceptable, but confirm.
- **`${CLAUDE_PLUGIN_ROOT}`** is used in `.mcp.json` and `hooks/hooks.json`; the
  hook also passes it through `env` so `run.py` resolves paths. Confirm expansion.

> **Changed 2026-10-15 (later):** the `age:` link to the user's personal store
> and the `sudo_hosts` config were replaced by the gateway's own vault
> (`~/.config/net-gateway/`, own age key), managed in chat with `/secret` and
> `/sudo` through a UserPromptSubmit hook that blocks the prompt (verified
> headless: the model never runs, and the transcript copy is scrubbed). See
> README. Tests: 171.
>
> **Added 2026-10-15:** an `age:` secret backend (pixi now pins `age` 1.3.2 on all
> five platforms) and a `run_privileged` tool (sudo locally or over ssh,
> `sudo_hosts`, always asks through elicitation, so its settings rule is
> `allow`). `settings.proposed.json` also adds deny rules for `Bash(age:*)`,
> `Bash(secret:*)`, reading `~/.config/age/**` and `~/.config/secrets/**`, and
> editing the plugin's `config/**`. Tests: 142.

```bash
# 2. Register the local marketplace and install

#    (see section 7) and verify the server + /net-log work.
```
